# 補足 1: Bash / ターミナル操作ガイド — コマンドの意味を理解する

**種別**: 参照資料（「このコマンドは何をしているの？」と思ったときに開く辞書）
**関連チャプター**: 全チャプター共通

---

## この補足資料の使い方

カリキュラムを進めていると、ターミナルにコマンドを入力する場面がたびたびあります。Claude Code が自動で実行することも多いですが、「このコマンドって何をしているの？」「なぜこう書くの？」と疑問を持ったら、この資料を開いてください。

**コマンドを暗記する必要はありません。** この資料の目的は「コマンドを自分で打てるようになること」ではなく、**「ターミナルで何が起きているかを理解して、安心して使えるようになること」**です。

---

## 1. ターミナルとシェルとは

**結論から言うと、ターミナルは「コンピューターへの命令書を直接渡す窓口」です。**

> [!NOTE]
> **ターミナルとは？** 文字を打ってコンピューターに命令する操作画面のことです。ファイルを開いたり、プログラムを起動したりするのをマウスではなく「テキスト」で行います。「コマンドライン」「CLI（シーエルアイ）」とも呼ばれます。

> [!NOTE]
> **シェルとは？** ターミナルで打った文字（コマンド）を解釈して、コンピューターに伝える通訳プログラムです。macOS には複数種類のシェルがありますが、日常的に意識する必要はほとんどありません。

**たとえ話:** ターミナルは「コンビニの発注端末」のようなものです。店員さん（あなた）が「この商品を 10 個発注して」と端末（ターミナル）に打ち込むと、本部のシステム（コンピューター）に伝わって処理されます。GUI（グラフィカルな画面）は「タッチパネル」で、ターミナルは「キーボードで直接打ち込む発注端末」のイメージです。

ターミナルを使うメリットは 3 つあります。

- **素早い**: マウスで何画面も開くより、コマンド 1 行で済む
- **正確**: 曖昧さがなく、書いた通りに実行される
- **自動化できる**: 繰り返し作業をスクリプトにまとめられる

このカリキュラムでは Claude Code がターミナル操作をほとんど代わりに行います。あなたが自分で打つコマンドは `claude` の起動など、最小限です。

---

## 2. 使っている環境の確認

このカリキュラムでは **Mac** と **Windows（WSL Ubuntu）** の 2 種類の環境を対象にしています。どちらを使っているかで、シェルと設定ファイルが異なります。

| | Mac | Windows（WSL Ubuntu） |
|--|-----|----------------------|
| **デフォルトシェル** | zsh（Catalina 2019年以降） | bash |
| **設定ファイル** | `~/.zshrc` | `~/.bashrc` |
| **ホームディレクトリ** | `/Users/yourname` | `/home/yourname` |

> [!NOTE]
> **WSL とは？** Windows の中で Linux（Ubuntu）を動かす仕組みです。「Windows Subsystem for Linux」の略で、Windows ユーザーが Mac と同じような開発環境を使えるようになります。

基本的なコマンド（`ls`、`cd`、`mkdir` など）は **Mac でも WSL でも同じように使えます**。違いが出るのは設定ファイルの場所とホームディレクトリのパスだけです。

### シェルと設定ファイルの詳細

**Mac の場合:**

macOS Catalina（2019年）以降、デフォルトのシェルは **zsh** です。設定ファイルは `~/.zshrc` です。

```bash
# bash
echo $SHELL
# → /bin/zsh と表示されれば zsh
```

**Windows（WSL Ubuntu）の場合:**

WSL の Ubuntu では **bash** がデフォルトです。設定ファイルは `~/.bashrc` です。

```bash
# bash
echo $SHELL
# → /bin/bash と表示されれば bash
```

## 3. パスの概念

### パス（Path）とは

**結論: パスは「ファイルやフォルダの住所」です。**

> [!NOTE]
> **パスとは？** コンピューター上のファイルやフォルダの場所を文字で表したものです。「このファイルはどこにあるか」を正確に指定するために使います。

**たとえ話:** パスは「住所」のようなものです。「東京都渋谷区〇〇町1-2-3」のように、大きな区分から小さな区分へと順番に書きます。コンピューターでは `/Users/yourname/myproject/src/index.ts` のように `/` で区切って書きます。

パスには 2 種類あります。

| 種類 | 書き方 | 例 | 特徴 |
|------|--------|-----|------|
| **絶対パス** | `/` から始まる | `/Users/yourname/myproject` | どこから見ても同じ場所を指す |
| **相対パス** | 今いる場所からの位置 | `./src` や `../other` | 「今いる場所」が基準になる |

> [!NOTE]
> **`/`（スラッシュ）とは？** ファイルシステムの「根っこ（ルート）」を表す記号です。絶対パスは必ずここから始まります。

### よく使う特殊記法

| 記法 | 意味 | 例 |
|------|------|----|
| `~` | ホームディレクトリの省略形（Mac: `/Users/yourname`、WSL: `/home/yourname`） | `~/myproject` |
| `.` | 今いるフォルダ（カレントディレクトリ） | `./src` |
| `..` | 1 つ上のフォルダ | `../other` |

> [!NOTE]
> **ホームディレクトリとは？** ターミナルを起動したときに最初にいる「自分の部屋」にあたるフォルダです。Mac では `/Users/yourname`、WSL Ubuntu では `/home/yourname`（`yourname` は自分のユーザー名）がホームディレクトリです。どちらも `~` と書くだけで省略できます。

### 隠しファイルとドットファイル

`.` で始まるファイル・フォルダは**隠しファイル**と呼ばれ、通常の `ls` コマンドでは表示されません。

```bash
# bash
# 通常の ls（隠しファイルは表示されない）
ls

# 隠しファイルも含む詳細表示
ls -la
```

`.zshrc` や `.env.local` はどちらも隠しファイルです。「ファイルが見つからない」と思ったら `ls -la` で確認してみてください。

> [!NOTE]
> **`ls -la` の `-la` とは？** `-l`（詳細表示）と `-a`（隠しファイルも表示）という 2 つのオプションを組み合わせたものです。オプションは「コマンドへの追加指示」で、`-` の後に文字を続けて書きます。

## 4. 基本コマンド集

### 場所・移動系

| コマンド | 動作 | 例 |
|---------|------|----|
| `pwd` | 今いる場所（フォルダ）を表示する | `pwd` |
| `ls` | 今いるフォルダの中身を一覧表示する | `ls` |
| `ls -la` | 隠しファイルも含む詳細一覧を表示する | `ls -la` |
| `cd フォルダ名` | 指定したフォルダに移動する | `cd myproject` |
| `cd ..` | 1 つ上のフォルダに移動する | `cd ..` |
| `cd ~` | ホームディレクトリに移動する | `cd ~` |
| `cd -` | 直前にいたフォルダに戻る | `cd -` |

> [!NOTE]
> **`pwd` とは？** 「Print Working Directory」の略で、「今作業しているフォルダを表示する」コマンドです。「今自分がどこにいるか」を確認したいときに使います。

**たとえ話:** `pwd` は「今いるフォルダの住所を表示する」コマンドです。迷子になったときに「今どこにいますか？」と聞く操作です。`cd` は「フォルダの中に入る」操作で、`cd ..` は「1 つ上の階に上がる」操作です。

### ファイル・フォルダ操作系

| コマンド | 動作 | 例 |
|---------|------|----|
| `mkdir フォルダ名` | フォルダを作成する | `mkdir myproject` |
| `touch ファイル名` | 空のファイルを作成する | `touch memo.txt` |
| `cp 元 先` | ファイルをコピーする | `cp file.txt backup.txt` |
| `mv 元 先` | ファイルを移動・名前変更する | `mv old.txt new.txt` |
| `rm ファイル名` | ファイルを削除する | `rm file.txt` |
| `rm -r フォルダ名` | フォルダごと削除する | `rm -r myproject` |

> [!WARNING]
> **注意: `rm` は元に戻せません。** ゴミ箱に入るのではなく、即座に完全削除されます。特に `rm -r` はフォルダの中身をすべて巻き込んで削除するため、実行前に必ず対象を確認してください。

### 確認・表示系

| コマンド | 動作 | 例 |
|---------|------|----|
| `cat ファイル名` | ファイルの中身を表示する | `cat memo.txt` |
| `which コマンド名` | コマンドの実体がどこにあるか確認する | `which node` |
| `echo 文字列` | 文字列や変数の値を表示する | `echo $PATH` |

> [!NOTE]
> **`which` とは？** 「このコマンドはどこにインストールされているか」を調べるコマンドです。`which node` で `node` の場所がわかります。「コマンドが使えない」と言われたときに、まずインストールされているか確認するために使います。

## 5. このカリキュラムでよく使うコマンド

カリキュラムを進める中で頻繁に登場するコマンドをまとめます。Claude Code が自動で実行するものも含みます。

| コマンド | 動作 |
|---------|------|
| `claude` | Claude Code を対話型で起動する |
| `claude -w 名前` | Worktree（別の机）を作って Claude Code を起動する |
| `claude --continue` | 直前のセッションを再開する |
| `git status` | Git の変更状態を確認する |
| `git log --oneline` | コミット履歴を 1 行ずつ確認する |
| `gh issue list` | GitHub の Issue 一覧を確認する |
| `gh pr list` | GitHub の PR 一覧を確認する |
| `npm run dev` | 開発サーバーを起動する |

> [!NOTE]
> **`npm run dev` とは？** アプリを「開発モード」で起動するコマンドです。`npm` は Node.js というプログラム環境のパッケージ管理ツールで、`run dev` は「`dev` という名前のスクリプトを実行する」という意味です。アプリを手元で確認したいときに使います。

## 6. 設定ファイルの使い方（`.zshrc`）

### `.zshrc` とは

**結論: `.zshrc` は「ターミナルの設定書」です。毎回ターミナルを開くたびに自動で読み込まれます。**

> [!NOTE]
> **`.zshrc` とは？** ターミナル（zsh）を新しく起動するたびに自動で実行される設定ファイルです。エイリアス（コマンドの短縮）、環境変数、PATH の設定などを書いておきます。ホームディレクトリ（`~/`）に置かれます。

**たとえ話:** `.zshrc` は「オフィスに出勤したときに毎朝行うルーティン」のようなものです。「まずメールを確認して、カレンダーを開いて、好みのフォントでエディタを起動する」というルーティンをファイルに書いておくと、ターミナルを開くたびに自動でセットアップが完了します。

> [!NOTE]
> **WSL Ubuntu の場合は？** `~/.zshrc` の代わりに `~/.bashrc` に同じ内容を書いてください。エイリアス・export・PATH の書き方は zsh とほぼ同じです。

### `.zshrc` に書く内容

#### 1. エイリアス（コマンドの短縮）

よく使うコマンドを短い別名で呼び出せるようにします。

```bash
# bash
# ll と打つだけで ls -la を実行する
alias ll='ls -la'

# myapp と打つだけによく使うフォルダに移動する
alias myapp='cd ~/workspace/my-todo-app'
```

> [!NOTE]
> **エイリアスとは？** 「別名」という意味です。長いコマンドに短い名前をつけることで、毎回の入力を省力化できます。

#### 2. 環境変数の設定

プログラムが参照する設定値を登録します。

```bash
# bash
# 開発環境であることをプログラムに伝える
export NODE_ENV=development
```

> [!NOTE]
> **環境変数とは？** プログラムが参照できる「名前のついた変数」です。`export 変数名=値` の形式で設定します。設定した変数は、その後に起動したプログラムすべてから参照できます。

#### 3. PATH の追加

新しくインストールしたコマンドをターミナルで使えるようにします。

```bash
# bash
# インストールしたツールをターミナルで使えるようにする
export PATH="$PATH:/usr/local/bin"
```

> [!NOTE]
> **PATH とは？** コマンドを実行したとき、ターミナルがそのコマンドを探しに行く「フォルダの一覧」です。`which node` などで「コマンドが見つからない」と言われるのは、そのコマンドが PATH に含まれていないフォルダにインストールされているためです。

### 設定を反映する方法

`.zshrc` を編集した後、設定を反映するには次のどちらかを行います。

- **ターミナルを再起動する** — 次回の起動から自動で反映される
- **`source` コマンドを実行する** — 今のターミナルに即反映される（再起動不要）

```bash
# bash
# Mac（zsh）の場合
source ~/.zshrc

# WSL Ubuntu（bash）の場合
source ~/.bashrc
```

> [!NOTE]
> **`source` とは？** 指定したファイルの内容を「今のターミナル」でそのまま実行するコマンドです。`source ~/.zshrc` を実行すると、ターミナルを再起動せずに `.zshrc` の設定が反映されます。

**たとえ話:** `.zshrc` を編集してターミナルを再起動するのは「設定を保存してパソコンを再起動する」イメージです。`source ~/.zshrc` は「再起動なしに設定を今すぐ反映する」——電源を入れたまま設定を更新するイメージです。

## 7. まとめ — クイックリファレンス

### 場所・移動

```bash
# bash
# 今いる場所を確認する
pwd

# フォルダの中身を確認する（隠しファイルも含む）
ls -la

# フォルダに移動する
cd myproject

# 1 つ上のフォルダに移動する
cd ..

# ホームディレクトリに移動する
cd ~
```

### ファイル・フォルダ操作

```bash
# bash
# フォルダを作成する
mkdir myproject

# ファイルをコピーする
cp file.txt backup.txt

# ファイルの名前を変更する（または移動する）
mv old.txt new.txt

# ファイルを削除する（元に戻せない）
rm file.txt

# フォルダごと削除する（元に戻せない）
rm -r myproject
```

### このカリキュラムでよく使うコマンド

```bash
# bash
# Claude Code を起動する
claude

# Worktree を作って起動する
claude -w feat_user_auth

# 前の作業を続ける
claude --continue

# Git の状態を確認する
git status

# コミット履歴を確認する
git log --oneline
```

### `.zshrc` の操作

```bash
# bash
# Mac（zsh）: 設定ファイルを VS Code で開く
code ~/.zshrc

# WSL Ubuntu（bash）: 設定ファイルを VS Code で開く
code ~/.bashrc

# 変更を今すぐ反映する
source ~/.zshrc    # Mac（zsh）の場合
source ~/.bashrc   # WSL Ubuntu（bash）の場合
```

### パスの記法まとめ

| 記法 | 意味 |
|------|------|
| `/` から始まる | 絶対パス（ルートから始まる完全な住所） |
| `~` | ホームディレクトリ（Mac: `/Users/yourname`、WSL: `/home/yourname`） |
| `.` | 今いるフォルダ |
| `..` | 1 つ上のフォルダ |
| `.` で始まるファイル名 | 隠しファイル（`ls -la` で表示される） |

> [!TIP]
> **覚えておきたい一文:** コマンドを暗記する必要はありません。「`pwd` で今いる場所を確認して、`cd` で移動して、`ls -la` で中身を見る」——この 3 つだけ押さえれば、ターミナルで迷子になっても必ず帰れます。
