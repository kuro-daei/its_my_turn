# Module 2: プロジェクト初期化

**所要時間**: 約 1 時間
**ゴール**: Next.js アプリが `http://localhost:3000` で動いている + Git ブランチ戦略が整っている
**学ぶ Claude Code 機能**: スキャフォールド指示、Git 操作

---

## このモジュールで学ぶこと

- Claude Code に「アプリの骨格を作って」と頼む方法
- Git でバージョン管理を始める方法
- ブランチを使った安全な開発の進め方
- Claude Code がプロジェクト全体を理解していることを体感する

**このモジュールが終わるとどうなる?**

ブラウザで `http://localhost:3000` を開くと、自分のアプリが表示されるようになります。料理のたとえだと「食材と調理器具が揃い、キッチンの準備ができた」状態です。次のモジュールからいよいよ「調理（機能作り）」に入ります。

## 事前確認

作業を始める前に、現在のブランチ（Git の「作業場所」）を確認してください。

> **ブランチとは?** 書類のコピーを作って、コピーの方で下書きするイメージです。オリジナル（main ブランチ）を汚さずに、コピー（feature ブランチ）で自由に試せます。気に入ったらオリジナルに反映、気に入らなければコピーを捨てればいいだけです。

```bash
git branch --show-current
```

> **注意:** `main` と表示された場合は、そのまま作業せずに、まず作業ブランチを作成してください。ブランチを作る手順は Step 2 で説明します。わからなければメンターに声をかけてください。

## Step 1: Next.js スキャフォールド（20分）

### 「スキャフォールド」って何?

スキャフォールド（scaffold）は建設現場の「足場」という意味です。アプリ開発では「アプリの骨格・ひな形を自動で作ること」を指します。

ゼロからファイルを一つひとつ作るのではなく、「Next.js アプリの標準的な構成」を一括で生成してもらいます。

### Claude Code への指示

まず Claude Code を起動します。

```bash
claude
```

起動したら、以下の指示をそのまま入力してください。

> Next.js プロジェクトを初期化して。TypeScript、Tailwind CSS、App Router、src ディレクトリ構成で

> **体験ポイント:** 「npx create-next-app --typescript --tailwind ...」のような専門的なコマンドを覚えなくても大丈夫です。自然な日本語で指示するだけで、Claude Code が適切なコマンドを判断して実行します。

[screenshot: Claude Code がコマンドを提案・実行している様子]

### 実行されるコマンド

Claude Code は内部で以下のコマンドを実行します。参考として記載しておきますが、覚える必要はありません。

```bash
npx create-next-app@latest . --typescript --tailwind --eslint --app --src-dir --import-alias "@/*"
```

インタラクティブに質問される場合は、Claude Code が自動で回答するか、以下を参考に答えてください。

| 質問 | 選択 |
|------|------|
| TypeScript を使いますか? | Yes |
| ESLint を使いますか? | Yes |
| Tailwind CSS を使いますか? | Yes |
| `src/` ディレクトリを使いますか? | Yes |
| App Router を使いますか? | Yes |
| Import エイリアスを変更しますか? | No（デフォルトのまま） |

### 各オプションの意味

**TypeScript（タイプスクリプト）**
JavaScript に「型」を追加した言語です。「この箱には数字しか入れてはいけない」というルールをコードに書けるので、間違いをコードを書く段階で見つけてくれます。「型チェック付きの JavaScript」とも呼ばれます。

**Tailwind CSS（テイルウィンド シーエスエス）**
デザインを整えるためのツールです。`className="text-blue-500 font-bold"` のようにクラス名を書くだけで色やフォントが変わります。CSS（ウェブページの見た目を決める言語）を直接書く必要がなくなります。

**App Router（アップ ルーター）**
Next.js の最新のページ管理方式です。`src/app/` フォルダの中にファイルを置くだけでページが作られます。「`src/app/about/page.tsx` というファイルを作ると、`/about` というページができる」という仕組みです。

**src ディレクトリ**
アプリのコードを `src/`（ソース）フォルダにまとめる構成です。設定ファイルとアプリコードが混ざらないので整理しやすくなります。

### 生成されるファイル構成

スキャフォールド後、主要なファイルは以下のようになります。

```
its_my_turn/
├── src/
│   └── app/
│       ├── layout.tsx        # アプリ全体の外枠（ヘッダーなど共通部分）
│       ├── page.tsx          # トップページ（localhost:3000 で表示されるページ）
│       └── globals.css       # 全体に適用されるデザイン設定
├── public/                   # 画像などの静的ファイル置き場
├── next.config.ts            # Next.js の設定ファイル
├── tailwind.config.ts        # Tailwind CSS の設定ファイル
├── tsconfig.json             # TypeScript の設定ファイル
├── package.json              # プロジェクトの依存パッケージ一覧（材料リストのようなもの）
└── CLAUDE.md                 # Claude Code への指示ファイル（Module 1 で作成済み）
```

> **注意:** `node_modules/` フォルダが自動生成されますが、中に大量のファイルが入っています。Git には登録しないので心配しなくて大丈夫です（`.gitignore` で自動的に除外されます）。

> **`node_modules/` とは?** アプリが動くために必要な「材料（ライブラリ）」が入ったフォルダです。数千〜数万個のファイルが入ることもありますが、`package.json` があれば `npm install` コマンドで自動再生成できるので、Git には含めません。

### 確認ポイント

- [ ] `src/app/page.tsx` が存在する
- [ ] `src/app/layout.tsx` が存在する
- [ ] `package.json` に `"next"` が含まれている
- [ ] エラーメッセージが表示されていない

## Step 2: Git 初期化 & ブランチ戦略（20分）

### Git でバージョン管理を始める理由

> **なぜ Git を使うの?** コードはどんどん変わります。「昨日の状態に戻したい」「この機能を試してみたいけど、うまくいかなかったら元に戻したい」というとき、Git がなければ毎回手動でファイルをコピーして保管しなければなりません。Git を使えば「いつでも過去の任意の状態に戻せる」のです。

#### 2-1. Git リポジトリを初期化する

Claude Code の会話で、以下のように指示します。

> git を初期化して、.gitignore を確認してから、最初のコミットをして

または、ターミナルで直接実行することもできます。

```bash
git init
```

> **`git init`（ギット イニット）とは?** このフォルダを Git で管理し始めることを宣言するコマンドです。実行すると `.git/` という隠しフォルダが作られ、そこにすべての変更履歴が保存されていきます。

`.gitignore`（ドット ギット イグノア）が正しく設定されているか確認します。

```bash
cat .gitignore
```

> **`cat`（キャット）コマンドとは?** ファイルの中身を画面に表示するコマンドです。`cat ファイル名` で中身を確認できます。

`node_modules` や `.env.local` などが記載されていることを確認してください。Next.js が自動生成する `.gitignore` には通常これらが含まれています。

[screenshot: .gitignore の内容が表示されている様子]

#### 2-2. Claude Code に初回コミットを頼む

> 現在のファイルをすべてステージングして、初回コミットをして。コミットメッセージは Conventional Commits 形式で

> **「ステージング」とは?** Git でファイルを保存する前の「下書き確認」のステップです。変更したファイルを「コミット（保存）する候補」として選ぶ作業です。

Claude Code はコミットメッセージを自動で考えてくれます。期待される出力の例:

```bash
git add .
git commit -m "feat: initialize Next.js project with TypeScript, Tailwind CSS, and App Router"
```

> **体験ポイント:** Claude Code はコミットメッセージのベストプラクティス（Conventional Commits）を知っています。「コミットして」と頼むだけで、適切な形式のメッセージを自動で作成してくれます。

### Conventional Commits（コンベンショナル コミッツ）とは

コミットメッセージを「種類: 説明」の形式で書くルールです。チームで開発するときに、変更の目的が一目でわかるようになります。

> **なぜこのルールが必要?** 「ちょっと変更した」「いろいろ修正」のようなコミットメッセージが続くと、後で「この変更は何だったっけ？」となります。ルールに従えば、変更の種類と内容が一目でわかります。

| プレフィックス | 意味 | 使用例 |
|--------------|------|--------|
| `feat:` | 新しい機能を追加 | `feat: add todo list component` |
| `fix:` | バグを修正 | `fix: resolve login error` |
| `docs:` | ドキュメントを変更 | `docs: update README` |
| `refactor:` | 機能を変えずにコードを整理 | `refactor: extract helper functions` |
| `style:` | コードの見た目を変更（動作は変えない） | `style: format with prettier` |
| `chore:` | ビルドや設定ファイルの変更 | `chore: update dependencies` |

### CLAUDE.md にブランチ命名規則を追記する

CLAUDE.md にブランチのルールを追加することで、Claude Code が自動的にそのルールに従うようになります。

> CLAUDE.md に以下のブランチ命名規則を追記して

```markdown
## Git ブランチ戦略

### ブランチ命名規則

- `feature/` — 新機能の開発
- `fix/` — バグの修正
- `refactor/` — リファクタリング（機能変更なし）
- `docs/` — ドキュメントの更新

### ルール

- **main ブランチへの直接コミットは禁止**
- 作業は必ずブランチを作成してから始める
- コミット前に `git branch --show-current` でブランチを確認する
```

> **体験ポイント:** CLAUDE.md にルールを書いておくと、Claude Code は毎回そのルールを参照します。「main にコミットして」と指示しても、Claude Code がブランチを作るよう促してくれるようになります。これが「引き継ぎメモの力」です。

[screenshot: CLAUDE.md にブランチルールが追記された様子]

### feature/setup ブランチを作成する

今後の作業用ブランチを作成します。Claude Code に指示するか、直接コマンドを実行します。

> feature/setup ブランチを作成して、そのブランチに切り替えて

```bash
git checkout -b feature/setup
```

> **`git checkout -b`（ギット チェックアウト）とは?** 新しいブランチを作成して、そこに切り替えるコマンドです。`-b` は「branch（ブランチ）を作る」オプションです。書類のコピーを作って、そのコピーの編集を始めるイメージです。

現在のブランチを確認します。

```bash
git branch --show-current
```

`feature/setup` と表示されれば成功です。

[screenshot: feature/setup ブランチに切り替わっている様子]

### 確認ポイント

- [ ] `git log --oneline` で初回コミットが表示される
- [ ] `git branch --show-current` で `feature/setup` と表示される
- [ ] CLAUDE.md にブランチ命名規則が追記されている
- [ ] `git status` で `nothing to commit` と表示される

> **`git status`（ギット ステータス）とは?** 現在の変更状況を確認するコマンドです。「どのファイルが変更されているか」「コミット待ちのファイルはあるか」がわかります。

## Step 3: 動作確認（20分）

### ローカルサーバーを起動する

> **ローカルサーバーとは?** 自分のパソコンの中だけで動くウェブサーバーのことです。インターネットには公開されておらず、自分のブラウザからだけアクセスできます。「自分のパソコンの中でアプリを動かして確認する」ための仕組みです。

> **注意:** 開発サーバーの起動はターミナルで直接実行します。Claude Code から起動すると、Claude Code のセッションが占有されてしまい、Claude Code に話しかけられなくなります。

新しいターミナルウィンドウを開いて、プロジェクトフォルダに移動してから以下を実行します。

```bash
npm run dev
```

以下のような出力が表示されれば成功です。

```
▲ Next.js 15.x.x
- Local:        http://localhost:3000
- Ready in 2.1s
```

[screenshot: npm run dev の実行結果]

### ブラウザで確認する

ブラウザを開いて `http://localhost:3000` にアクセスしてください。

> **`localhost:3000` とは?** `localhost`（ローカルホスト）は「自分のパソコン」を指す特別なアドレスです。`3000` はポート番号（部屋番号のようなもの）です。

Next.js のウェルカムページが表示されれば、アプリが正常に動いています。

[screenshot: ブラウザに Next.js のウェルカムページが表示されている様子]

> **注意:** ポート `3000` が他のアプリで使用中の場合、`3001` や `3002` など別のポートが自動的に使われます。ターミナルの出力を確認してください。

### Claude Code にプロジェクト構造を説明してもらう

Claude Code のセッション（別のターミナル）に戻り、以下のように指示します。

> src/ の中身を説明して

Claude Code からは以下のような応答が期待されます。

---

**期待される応答の概要:**

```
src/ ディレクトリには Next.js App Router の主要ファイルが含まれています。

app/layout.tsx
  アプリ全体のレイアウトを定義するファイルです。<html> タグや <body> タグ、
  全ページ共通のメタデータ（タイトル、説明など）がここに定義されています。
  Tailwind CSS の globals.css もここでインポートされています。

app/page.tsx
  localhost:3000 にアクセスしたときに表示されるトップページです。
  現在は Next.js のデフォルトのウェルカム画面が表示されています。
  このファイルを編集することで、トップページの内容を変更できます。

  アプリ全体に適用されるスタイルシートです。
  Tailwind CSS の基本スタイルがインポートされています。
```

---

> **体験ポイント:** Claude Code は自分でファイルを読み込んで、プロジェクト全体の構造を理解しています。「このファイルは何をするの?」「このコードはどういう意味?」と聞くだけで、丁寧に説明してくれます。理解のスタート地点として大いに役立ちます。

## トラブルシューティング

### `npx create-next-app` が失敗する

まず Node.js のバージョンを確認してください。v18 以上が必要です。

```bash
# Node.js のバージョンを確認（v18 以上が必要）
node --version

# npm を最新版に更新
npm install -g npm@latest
```

### `npm run dev` でエラーが出る

```bash
# node_modules を再インストール
rm -rf node_modules
npm install
```

> **`rm -rf node_modules`（アールエム）とは?** `node_modules` フォルダを削除するコマンドです。その後 `npm install` を実行すると、`package.json` の内容を元に再生成されます。エラーが出たときの「おまじない」として覚えておいてください。

### ポートが使用中と表示される

```bash
# 別のポートで起動
npx next dev -p 3001
```

### Claude Code が `git` コマンドを実行しない

以下のように明示的に許可を伝えてください。

> git コマンドの実行を許可します。git init して初回コミットをして

## このモジュールのまとめ

このモジュールでは、アプリ開発の「土台」を作りました。

- **Next.js スキャフォールド**: 日本語で指示するだけで、Claude Code がアプリの骨格を一括生成しました
- **Git 初期化**: バージョン管理を始め、「いつでも過去に戻れる」状態にしました
- **ブランチ戦略**: CLAUDE.md にルールを書くことで、Claude Code が自動的にブランチ管理を守るようになりました
- **動作確認**: ブラウザで `http://localhost:3000` にアクセスし、アプリが実際に動くことを確認しました

次の Module 3 では、Figma MCP を使ってデザインを自動生成し、そのデザインをそのまま Next.js のコードに変換する体験をします。

> **Module 3 に進む前に:** 開発サーバーを停止してください。ターミナルで `Ctrl + C` を押すと停止できます。
