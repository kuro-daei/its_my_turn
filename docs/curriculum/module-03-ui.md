# Module 3: UI を作る

**所要時間**: 約 1.5 時間
**ゴール**: Figma でデザインした TODO リストが Next.js で表示される
**学ぶ Claude Code 機能**: Figma MCP（双方向連携）、プロンプティング、反復修正

---

## このモジュールで学ぶこと

- Claude Code から Figma を直接操作してデザインを生成する方法
- Figma のデザインを確認・手動調整する方法
- Figma のデザインを Next.js のコードに変換する方法
- 「作る → 確認 → 修正」の反復サイクルで完成度を上げる方法
- UI をコンポーネント（部品）に分割する考え方

---

このモジュールでは、「デザインツール（Figma）と開発ツール（Claude Code）が直接会話する」体験をします。

人間がやることは「指示を出す」と「確認・調整する」だけ。あとは Claude Code と Figma が協力して UI（ユーザーインターフェース）を作り上げます。

> **UI（ユーザーインターフェース）とは?** ユーザーが実際に見て触れる画面のことです。ボタン、入力欄、リストなど、画面に表示される要素すべてを指します。「見た目」とほぼ同じ意味で使われます。

**3つのステップの流れ:**

```
Step 1: Claude Code が Figma にデザインを作る   （30分）
Step 2: あなたが Figma でデザインを確認・調整する（20分）
Step 3: Claude Code がデザインをコードに変える   （40分）
```

**なぜこの順番なの?**

「デザイン → 確認 → コード化」という流れは、実際のプロ現場でも使われるワークフローです。AI が 80% 作って、人間が 20% 磨く。そのサイクルを体験します。

---

## Step 1: Claude Code から Figma にデザインを生成する（30分）

### 何が起きるのか

Claude Code に「Figma にデザインを作って」と頼むと、Claude Code は **Figma MCP** というしくみを使って Figma を直接操作します。あなたが Figma を開かなくても、Claude Code が自動でフレームやテキスト、ボタンを配置していきます。

> **Figma（フィグマ）とは?** デザイナーが画面のデザインを作るためのツールです。ブラウザ上で動き、チームで共同編集できます。今回は「設計図を描く場所」として使います。

> **Figma MCP の威力を感じてみましょう。** 通常、デザインを作るには Figma を開いて、マウスで一つひとつ要素を配置していきます。しかし Figma MCP を使えば、Claude Code が Figma を直接操作してデザインを自動生成できます。Claude Code は「会話するだけ」のツールではなく、外部の専門ツールを実際に操作できます。

[screenshot: Claude Code のターミナルと Figma の画面を並べて表示。Claude Code が操作中、Figma の画面がリアルタイムで変わっていく様子]

### 事前確認

Step 1 を始める前に、以下を確認してください。

- [ ] Module 1 で Figma MCP の接続が完了している
- [ ] Figma にログインしている
- [ ] Figma に空のプロジェクト（または新規ファイルを作れる状態）がある
- [ ] Claude Code が起動している（プロジェクトルートで `claude` を実行）

> **注意:** Figma MCP が設定されていない場合は、Module 1 の Step 2「MCP サーバーの設定」に戻って Figma MCP を接続してください。

### Claude Code への指示

Claude Code のチャット画面に、以下をそのままコピーして貼り付けてください。

> TODO アプリの UI を Figma にデザインして。以下の要素を含めて:
> - TODO リスト表示エリア（TODO がない場合のメッセージも含む）
> - 新規 TODO 追加フォーム（テキスト入力欄と「追加」ボタン）
> - 各 TODO アイテムに完了チェックボックスと削除ボタン
> - シンプルでモダンなデザイン（白背景、アクセントカラーは青系）
> - スマートフォン幅（375px）で見やすいレイアウト

> **プロンプティング（指示の書き方）のコツ:** 「いい感じにして」よりも「白背景、青系、375px」のように具体的に書くと、Claude Code は意図通りのデザインを作りやすくなります。ただし、やり取りしながら修正できるので、完璧な指示でなくても大丈夫です。

### Claude Code が実行する操作

Claude Code は以下の順番で Figma を操作します。この間、あなたは待っていてください。

1. Figma に新しいフレーム（ページの骨格）を作成する
2. フレームのサイズを 375px（スマートフォン幅）に設定する
3. ヘッダー部分（アプリ名「TODO」のテキスト）を配置する
4. TODO 追加フォーム（入力欄 + ボタン）を配置する
5. TODO リストエリアを配置する
6. サンプルの TODO アイテムを 3〜4 個配置する（チェックボックス、テキスト、削除ボタン付き）
7. 空の状態のメッセージ（「TODO はまだありません」）を配置する
8. 色・フォント・余白を整える

> **フレームとは?** Figma で「画面一枚分」を表す要素です。スマートフォンの画面サイズに合わせて枠を作り、その中にデザインを配置します。

[screenshot: Figma 上に生成された TODO アプリのデザイン全体像]

### 確認ポイント

Claude Code の作業が終わったら、Figma を開いて以下を確認してください。

- [ ] Figma に新しいフレームが作成されている
- [ ] ヘッダー、追加フォーム、リストエリアの 3 つのエリアが揃っている
- [ ] TODO アイテムにチェックボックスと削除ボタンが含まれている
- [ ] 全体的に読みやすいレイアウトになっている

### うまくいかない場合

**Claude Code がエラーを返した場合:**

まず `claude /mcp` と入力して MCP の接続状況を確認します。Figma MCP が「connected」になっていない場合は、Module 1 に戻って再接続してください。

> **`claude /mcp`（スラッシュ エムシーピー）とは?** Claude Code に接続中の MCP サーバーの一覧と状態を表示するコマンドです。

**デザインが思ったものと全然違う場合:**

心配ありません。次の Step 2 で手動調整できます。また、以下のように追加指示を出すことも可能です。

> 今の Figma のデザインを作り直して。カラーはグレー系にして、ヘッダーはもっとシンプルに

## Step 2: Figma でデザインを確認・調整する（20分）

### このステップの目的

Claude Code が生成したデザインは「たたき台」です。あなたの好みやイメージに合わせて、Figma 上で手動調整します。

> **AI と人の協業パターンです。** AI に 100% 完璧を求めるのではなく、AI に 80% 作らせて人が 20% 磨く、という流れが効率的です。大きな方向性は AI に任せ、細かい調整や最終判断は人間が行います。

[screenshot: Figma 上でデザインを選択・編集している様子]

### Figma の基本操作（初めての方向け）

Figma を初めて触る方のために、最低限の操作を説明します。間違えても `Ctrl+Z`（Mac は `Cmd+Z`）で元に戻せるので安心してください。

**要素を選択する:**
デザイン上の要素（テキスト、ボタンなど）をクリックすると選択できます。複数選択したい場合は `Shift` キーを押しながらクリックします。

**プロパティを変更する（右パネル）:**
要素を選択すると、Figma の右側に「デザイン」パネルが表示されます。ここで色、フォントサイズ、余白などを変更できます。

**テキストを変更する:**
テキスト要素をダブルクリックすると文字を編集できます。

**色を変更する:**
要素を選択 → 右パネルの「Fill」（塗りつぶし）の色をクリック → カラーピッカーで変更します。

### 確認するポイント

以下の観点でデザインを見ていきましょう。問題があれば手動で調整するか、後ほど Claude Code への指示で修正します。

#### レイアウト（全体の配置）

画面を上から下へ自然に読めるか確認します。

- [ ] ヘッダー → 追加フォーム → リスト の順番になっているか
- [ ] 要素が画面の端に詰まりすぎていないか（余白が適切か）
- [ ] 全体的に縦一列で読み下せる構成になっているか

[screenshot: レイアウトのよい例と悪い例を横に並べた比較]

#### 色使い

色は「見やすさ」と「わかりやすさ」の両方に影響します。

- [ ] 背景と文字のコントラストが十分か（薄い色の背景に薄い色の文字は NG）
- [ ] ボタンの色が目立っているか
- [ ] 完了済み TODO は通常の TODO と視覚的に区別されているか（グレーアウトなど）

#### フォントサイズ

文字の大きさに「序列」があるか確認します。

- [ ] ヘッダーのタイトルが一番大きいか
- [ ] TODO のテキストが読みやすいサイズか（最低 14px 推奨）
- [ ] ボタンのラベルが読みやすいか

> **px（ピクセル）とは?** 画面の点（ドット）の数を表す単位です。14px は画面上の 14 個の点分の高さです。スマートフォンでは 14px 以下だと読みにくくなります。

#### 余白（スペース）

余白は「デザインの呼吸」です。詰めすぎると読みにくくなります。

- [ ] 各 TODO アイテムの間に適切な隙間があるか
- [ ] 追加フォームと TODO リストの間に十分な余白があるか
- [ ] 画面の左右に余白があるか（端から端まで要素が詰まっていないか）

### 手動調整のコツ

気になった部分があれば、以下の手順で調整してみてください。

**余白を広げたい場合:**
1. 調整したいフレームまたはコンテナを選択
2. 右パネルの「Padding」（内側の余白）の数値を変更
3. 見た目を確認しながら調整

**色を変えたい場合:**
1. 色を変えたい要素（ボタンなど）を選択
2. 右パネルの「Fill」をクリック
3. カラーピッカーから好みの色を選ぶ
4. または HEX コード（16進数カラーコード）を直接入力（例: `#3B82F6` は青）

**フォントサイズを変えたい場合:**
1. テキスト要素を選択
2. 右パネルの「Font size」の数値を変更

> **注意:** この段階での調整は「ざっくり方向性を決める」程度で構いません。細かい調整は Step 3 の反復修正フェーズで Claude Code に指示して行います。完璧を目指さなくて大丈夫です。

### 調整後の確認ポイント

- [ ] 全体のビジュアルイメージが気に入っているか
- [ ] TODO アプリとして「使いやすそう」に見えるか
- [ ] 特に気になる部分がないか（あれば後の指示でメモしておく）

## Step 3: Figma のデザインを Next.js コードに実装する（40分）

### Phase A: デザインをコードに変換する（15分）

#### Claude Code への指示

Figma でのデザイン調整が終わったら、Claude Code のチャット画面に以下を入力します。

> Figma の最新デザインを取得して、Tailwind CSS で実装して。Next.js の App Router で、`src/app/` 配下に作って。まず `src/app/page.tsx` にシンプルな構成で実装して

#### Claude Code が行う処理

1. Figma MCP を通じて、現在の Figma ファイルのデザインデータ（色、サイズ、レイアウト）を取得する
2. デザインデータを解析し、Tailwind CSS のクラス名に対応させる
3. `src/app/page.tsx` に React コンポーネントとして実装する

> **React（リアクト）とは?** Facebook（現 Meta）が開発した UI を作るためのライブラリです。画面をパーツ（コンポーネント）に分割して作る考え方で、Next.js はこの React を使っています。

> **コンポーネントとは?** 画面を構成する「部品」のことです。「ヘッダー部品」「ボタン部品」「リスト部品」のように、再利用可能なパーツとして作ります。レゴブロックのように組み合わせて画面を作ります。

[screenshot: Claude Code がコードを生成している様子と、ブラウザでの表示結果]

#### 実装結果の確認

コードが生成されたら、ブラウザで確認します。

```bash
# ターミナルで実行
npm run dev
```

ブラウザで `http://localhost:3000` を開いて、Figma のデザインと見比べてください。

**確認ポイント:**
- [ ] ページが正常に表示される（エラーが出ていない）
- [ ] 全体のレイアウトが Figma に近い
- [ ] 色やフォントが Figma と大体合っている
- [ ] TODO アイテムのサンプルが表示されている

### Phase B: 反復修正で仕上げる（15分）

実装結果を Figma デザインと比べながら、気になる点を Claude Code に指示して修正していきます。以下は典型的な修正指示の例です。**自分が気になる部分を自由に指示してください。**

#### 反復修正の指示例

**余白を調整したい場合:**

> 余白をもう少し広げて。特に各 TODO アイテムの上下の padding と、画面左右の margin を大きくして

**色を Figma に合わせたい場合:**

> ボタンの色を Figma のデザインに合わせて。今は灰色になっているけど、Figma では青（#3B82F6）になっているはず

**フォントサイズを調整したい場合:**

> タイトルのフォントサイズを少し大きくして。今の 1.5rem から 2rem くらいにして

> **rem（レム）とは?** 画面の文字サイズを表す単位です。`1rem` はブラウザの基本フォントサイズ（通常 16px）を 1 とした相対的な大きさです。`2rem` なら 32px です。px と違って、ユーザーのブラウザ設定に追従するメリットがあります。

**モバイル対応にしたい場合:**

> レスポンシブ対応して。スマートフォン（375px）とデスクトップ（1024px）の両方で見やすいようにして

> **レスポンシブとは?** 画面の大きさに応じてデザインが自動的に変わる仕組みのことです。スマートフォンでもパソコンでも見やすいように自動調整されます。

> **体験ポイント:** 「もう少し大きく」「Figma に合わせて」「モバイル対応」という自然な言葉で指示できます。これが**プロンプティング**（AI への指示の技術）です。曖昧な指示より具体的な指示の方が精度が上がりますが、完全に正確でなくてもやり取りしながら近づけられます。

#### 修正のサイクル

反復修正は以下のサイクルで繰り返します。

```
1. ブラウザで表示を確認する
   ↓
2. 気になる点を発見する
   ↓
3. Claude Code に具体的な修正指示を出す
   ↓
4. コードが更新される（ブラウザが自動更新）
   ↓
1. に戻る
```

このサイクルを 2〜3 回繰り返せば、かなり Figma のデザインに近い実装が完成します。

**反復修正の確認ポイント:**
- [ ] 余白が適切で、窮屈に感じない
- [ ] 色が Figma のデザインに近い
- [ ] フォントサイズが読みやすい
- [ ] スマートフォンで表示したときにも崩れない

### Phase C: コンポーネントに分割する（10分）

UI が完成したら、コードをコンポーネント（パーツ）に分割します。

> **なぜ分割するの?** 今は全部の画面要素が `page.tsx` というファイル一つに書かれています。このまま機能追加すると、ファイルが大きくなりすぎて読みにくくなります。「ヘッダーだけ変えたい」「フォームだけ修正したい」というときに、分割されていると目的のコードをすぐ見つけられます。

#### コンポーネント分割の指示

> このページを以下のコンポーネントに分割して。それぞれ `src/components/` に新しいファイルを作って:
> - `Header`: アプリのタイトル部分
> - `TodoList`: TODO アイテムの一覧表示エリア
> - `TodoItem`: 個々の TODO アイテム（チェックボックス、テキスト、削除ボタン）
> - `AddTodoForm`: 新規 TODO を入力・追加するフォーム

#### 分割後のファイル構成

Claude Code がコンポーネントを分割すると、以下のような構成になります。

```
src/
├── app/
│   └── page.tsx           # 各コンポーネントを組み合わせるルートページ
└── components/
    ├── Header.tsx          # アプリのタイトル・ヘッダー
    ├── TodoList.tsx        # TODO リスト全体のコンテナ
    ├── TodoItem.tsx        # 個々の TODO アイテム
    └── AddTodoForm.tsx     # TODO 追加フォーム
```

**`src/app/page.tsx` の役割:**

分割後の `page.tsx` はシンプルになります。各コンポーネントをインポート（読み込み）して並べるだけになります。

```tsx
// 分割後の page.tsx のイメージ
import Header from "@/components/Header";
import AddTodoForm from "@/components/AddTodoForm";
import TodoList from "@/components/TodoList";

export default function Home() {
  return (
    <main>
      <Header />
      <AddTodoForm />
      <TodoList />
    </main>
  );
}
```

> **`import`（インポート）とは?** 他のファイルに書かれた部品を「読み込む」命令です。`import Header from "@/components/Header"` は「`src/components/Header.tsx` というファイルに書かれている `Header` というコンポーネントをここで使えるようにする」という意味です。

> **注意:** 上記のコードはイメージです。実際に Claude Code が生成するコードは、props（データの受け渡し）の設計によって少し異なります。Claude Code が生成したコードをそのまま使ってください。

> **props（プロップス）とは?** コンポーネント間でデータを渡す仕組みです。「このリストに表示するデータを渡す」「このボタンが押されたときの処理を渡す」というように使います。詳しくは後のモジュールで学びます。

#### 分割後の確認

- [ ] `src/components/` フォルダに 4 つのファイルが作成されている
- [ ] `src/app/page.tsx` がシンプルな構成になっている
- [ ] ブラウザで表示が変わっていない（分割しただけで見た目は同じ）

[screenshot: src/components/ ディレクトリにファイルが並んでいる様子と、ブラウザの表示が変わっていない様子]

## このモジュールのまとめ

このモジュールでは、デザインから実装までの一連のワークフローを体験しました。

| 機能 | 体験した内容 |
|------|-------------|
| **Figma MCP** | Claude Code が Figma を直接操作してデザインを生成・取得できることを体験した |
| **プロンプティング** | 自然な言葉でデザインの修正指示を出し、意図通りに修正できることを体験した |
| **反復修正** | 「作る → 確認 → 修正」のサイクルで完成度を上げていく開発スタイルを体験した |
