# 補足 9: サブエージェントとチーム開発 — Claude に「役割」を与える

**種別**: 概念解説＋実践ガイド
**関連チャプター**: Chapter 2「Claude Code を整える」、Chapter 5「Issue とワークツリー」

---

## この記事を読むとわかること

- エージェントとは何か、どう定義するか
- 各エージェントに「できること・できないこと」を設定する方法（Permission）
- 複数のエージェントを同時並行で動かす方法
- CLAUDE.md とエージェント定義をチームで共有する方法

Claude Code は最初から「ひとりのアシスタント」として動きます。しかし、エージェント機能を使うと、Claude Code に「専門の担当者」を複数配置できるようになります。この記事では、その仕組みと実践的な設定方法を解説します。

---

## 結論: エージェントとは「専門家を呼び出す機能」

**エージェントとは、Claude Code に「役割と権限を与えたサブチームメンバー」です。**「記事を書く担当」「技術的な正確性をチェックする担当」「読みやすさをレビューする担当」のように、それぞれに専門領域と作業できる範囲を設定できます。

この記事では、以下の 4 つのトピックを順に解説します。

| セクション | 内容 | たとえ話での対応 |
|---|---|---|
| 1. エージェントの仕組み | `.claude/agents/` ディレクトリと定義ファイル | 業務説明書を書いてスタッフを雇う |
| 2. Permission 設定 | 権限の設定方法とフック | 「この担当者はどこまでできるか」を決める |
| 3. 並列エージェント | 複数エージェントを同時起動する | 複数メンバーが同時に作業する |
| 4. チームでの設定共有 | Git を使った設定ファイルの管理 | 業務マニュアルを Git で管理する |

## 1. エージェントの仕組み — 「業務説明書」を書いてスタッフを雇う

### たとえ話: 新しいチームメンバーへの「業務説明書」

新しいスタッフがチームに加わるとき、業務説明書を渡すことがあります。「あなたの担当は記事の編集です」「使ってよいシステムはこれとこれです」「担当フロアはここまでです」——そういった内容が書かれた書類です。

Claude Code のエージェントも同じです。エージェントごとに「業務説明書」を 1 つのファイルとして用意します。Claude Code がその業務説明書を読むことで、「この担当者は何をする人で、どこまでできるか」を把握します。

### 技術説明: `.claude/agents/` ディレクトリとは

エージェントの定義ファイルは、プロジェクトの `.claude/agents/` フォルダの中に置きます。**ファイル名がエージェントの ID**（呼び出し名）になります。

```text
my-project/
└── .claude/
    └── agents/
        ├── writer.md    ← writer エージェント
        ├── tech.md      ← tech エージェント
        └── chief.md     ← chief エージェント
```

各ファイルの先頭には **YAML フロントマター**（設定シート）を書きます。YAML はプログラミング言語ではなく、人間が読みやすい形式で書かれた「設定シート」の一種です。

> [!NOTE]
> **YAML（ヤムル）とは？** 「Yet Another Markup Language」の略。設定ファイルを記述するための書き方の一種です。インデント（字下げ）で構造を表現します。コードを書く必要はなく、「項目名: 値」の形式で設定を記述します。

以下は実際のプロジェクトで使われている `writer.md` のフロントマターを元にした例です。

```yaml
---
name: writer
description: "記事の作成・編集・校正を担当するエージェント。ドキュメントを書く・書き直す必要があるときに使う。"
tools: Read, Write, Edit, Glob, Grep
model: sonnet
color: yellow
allowedPaths:
  - docs/
---

あなたはプロの編集者です。
- 記事は日本語で書く
- 専門用語には必ず平易な説明をつける
```

YAML フロントマター（`---` と `---` で囲まれた部分）に続けて、エージェントへの「業務指示」を自由な文章で書くことができます。

### 各フィールドの役割

| フィールド | 役割 | たとえ話 |
|---|---|---|
| `name` | エージェントの名前（呼び出し時に使う） | スタッフの役職名 |
| `description` | いつこのエージェントを呼ぶかの説明 | 業務担当一覧に書かれた担当業務 |
| `tools` | 使えるツール（ファイル読み書き・検索など） | 使ってよいツール・システムの一覧 |
| `model` | 使う AI モデル | 担当者のスキルレベル指定 |
| `allowedPaths` | 編集できるフォルダの範囲 | 入室できるフロア・部屋 |

### Task tool によるエージェント起動の仕組み

エージェントは、**Claude Code の内部機能（Task tool）によって起動**されます。これはユーザーが直接操作するものではなく、メインの Claude Code（指揮者）が「この仕事はこのエージェントに任せよう」と判断したときに自動で呼び出される仕組みです。

指揮者であるメインエージェントが Task tool を通じてサブエージェントを呼び出し、サブエージェントが担当の作業を実行して結果を返す——という流れで動きます。

## 2. Permission（権限）設定 — 「この担当者はどこまでできるか」を決める

### たとえ話: 会社における業務権限

会社の中には「このシステムは使ってよい」「このフロアには入れない」という業務権限があります。経理担当は財務データの閲覧システムを使えますが、人事システムにはアクセスできない——そういった権限の区切りは、組織の安全のために欠かせません。

Claude Code のエージェントにも同様の「業務権限」を設定できます。

### 技術説明: `settings.json` の `permissions` 設定

プロジェクトの `.claude/settings.json`（設定ファイル）で、エージェント全体に対して「許可する操作」と「禁止する操作」を指定できます。JSON はプログラミング言語ではなく、設定ファイルの書き方の一種です。

> [!NOTE]
> **JSON（ジェイソン）とは？** 「JavaScript Object Notation」の略。データや設定を記述するための書き方の一種です。`{}` で囲んで、`"キー": "値"` の形式で設定を書きます。

```json
{
  "permissions": {
    "allow": [
      "Edit(docs/**)",
      "Write(docs/**)"
    ]
  },
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/restrict-to-docs.sh"
          }
        ]
      }
    ]
  }
}
```

### エージェント定義の `allowedPaths` との違い

「エージェント定義ファイル（`.md`）の `allowedPaths`」と「`settings.json` の `permissions`」は、それぞれ異なる層で権限を制御しています。

| 設定場所 | 設定単位 | 主な役割 |
|---|---|---|
| エージェント定義ファイル（`.md`）の `allowedPaths` | エージェントごと | このエージェントが作業できるフォルダを宣言する |
| `settings.json` の `permissions` | プロジェクト全体 | Claude Code 全体で許可・禁止する操作を決める |
| フック（hooks） | 操作のタイミングごと | 実際の操作時に自動でルールを強制する |

### フックによる制御: 「自動で動く審査係」

**フック（hooks）** とは、「ファイルを変更しようとするたびに自動で起動する審査係」です。設定した条件（例: ファイルを編集しようとした瞬間）に自動でスクリプトが走り、許可するかブロックするかを判定します。

このプロジェクトでは `.claude/hooks/restrict-to-docs.sh` というフックスクリプトが実際に動いています。サブエージェントが `docs/` フォルダ外のファイルを編集しようとした場合に、自動でブロックして「許可されていない範囲です」というエラーを返します。

フックの動作の流れは以下のとおりです。

```text
サブエージェントがファイルを編集しようとする
        ↓
PreToolUse フックが起動（操作の直前に自動実行）
        ↓
「docs/ 内のファイルか？」チェック
        ↓
YES → 編集を許可
NO  → ブロックしてエラーメッセージを返す
```

この仕組みにより、設定ファイルやシステムファイルへの意図しない変更を防ぐことができます。

> [!NOTE]
> **フック（hook）とは？** 「引っかける」という意味。Claude Code では、特定のタイミング（ファイル編集の直前・直後など）に自動で実行されるスクリプトのことを指します。人間がいちいち確認しなくても、ルールに基づいた審査が自動で行われます。

## 3. 並列エージェントの活用 — 「複数メンバーが同時に作業する」

### たとえ話: 同時並行作業

ドキュメントを作成するとき、「ライターが下書きを書いている間に、前のセクションのレビューを別の担当者が進める」ことができれば、全体の作業が速く終わります。Claude Code のエージェント機能でも、同じことができます。

### 技術説明: 並列エージェントの仕組み

**並列エージェント**とは、複数のエージェントを同時に起動して、異なる仕事を同時並行で進める機能です。

メインエージェント（指揮者）が複数のサブエージェントを同時に呼び出し、それぞれが独立したタスクを並列で処理します。全員が作業を終えたら、指揮者が結果をまとめます。

### ユースケース例

```text
メインエージェント（指揮者）
├── writer エージェント: セクション A の下書き作成
├── tech エージェント:   技術的な正確性チェック
└── chief エージェント:  非エンジニア向けの読みやすさレビュー
```

この例では、3 つのエージェントが同時並行で異なる作業を実行します。

### 並列実行のメリットと注意点

| 項目 | 内容 |
|---|---|
| **メリット: 処理速度** | 複数の作業を同時に進めるため、合計時間を短縮できる |
| **メリット: 専門性** | それぞれの得意分野に集中して、品質を高められる |
| **注意点: 依存関係** | 「A が終わらないと B が始められない」作業には不向き |
| **注意点: ファイルの競合** | 同じファイルを同時に編集すると、変更が上書きされる可能性がある |

### 並列実行 vs 順次実行の使い分け

| 方式 | 向いているケース | 例 |
|---|---|---|
| **並列実行** | 独立した作業を複数まとめて処理したい | 「複数セクションを同時に下書き」「下書きとレビューを同時進行」 |
| **順次実行** | 前の作業の結果を次の作業が必要とする | 「下書き → 校正 → 公開」のような工程管理 |

## 4. チームでの設定共有 — 「業務マニュアルを Git で管理する」

### たとえ話: 業務マニュアルの共有問題

チームで業務マニュアルを共有するとき、「最新版がどれかわからない」「自分の手元のファイルが古いバージョンだった」という問題が起きがちです。メール添付やチャット共有では、更新のたびに全員が手動で差し替える必要があります。

Git を使えば、エージェントの定義ファイルや設定ファイルを「チーム全員が常に最新版を参照できる形」で管理できます。

> [!NOTE]
> **Git とは？** ファイルの変更履歴を管理するシステムです。「誰が・いつ・何を変更したか」が記録され、チーム全員が同じ最新版を共有できます。詳細は補足 2 を参照してください。

### Git 管理すべきファイルと個人設定の分離

プロジェクトの設定ファイルには「チーム全員で共有すべきもの」と「個人の手元にだけ置くもの」があります。

```text
my-project/
├── CLAUDE.md                    ← Git 管理する（チーム共有）
└── .claude/
    ├── settings.json            ← Git 管理する（チーム共有）
    ├── settings.local.json      ← .gitignore に追加（個人設定）
    ├── agents/
    │   ├── writer.md            ← Git 管理する（チーム共有）
    │   └── tech.md              ← Git 管理する（チーム共有）
    └── hooks/
        └── restrict-to-docs.sh  ← Git 管理する（チーム共有）
```

`settings.local.json` は個人の設定（API キーの保管場所や個人の好みの設定など）を書くファイルです。`.gitignore` に追加することで、Git の管理対象から除外して「自分の手元だけ」に置いておけます。

### 新メンバーが参加したときの流れ

新しいメンバーが加わっても、3 ステップで環境を整えられます。

1. **リポジトリをクローン（コピー）する** — Git からプロジェクトのファイル一式を取得する
2. **Claude Code を起動する** — `.claude/agents/` のエージェント定義が自動で読み込まれる
3. **個人設定だけ手元で設定する** — `settings.local.json` に自分専用の設定を書く

エージェントの定義、フックの設定、CLAUDE.md の内容——これらはすべて Git から自動で取得できるため、手動でのセットアップ作業をほぼゼロにできます。

### 設定を更新・共有するワークフロー

エージェントの定義や設定を変更したいときは、通常のコード変更と同じワークフローで進めます。

1. **ブランチを作成する** — `git checkout -b feature/add-new-agent`
2. **`.claude/agents/` のファイルを編集する** — 新しいエージェントを追加・既存を修正
3. **Pull Request（プルリクエスト）を作成する** — チームメンバーにレビューを依頼
4. **レビューを経てマージする** — チーム全員の設定が一斉に更新される

この流れにより、「誰かが勝手に設定を変えていた」「古い設定のまま作業していた」といった問題を防げます。

### CLAUDE.md の階層（グローバル vs プロジェクト）

CLAUDE.md は複数の場所に置けます。それぞれの適用範囲が異なります。

| 配置場所 | 適用範囲 | 用途 |
|---|---|---|
| `~/.claude/CLAUDE.md` | すべてのプロジェクト（個人設定） | 自分の作業スタイルや好みの設定 |
| プロジェクトルートの `CLAUDE.md` | そのプロジェクト全体（チーム共有） | プロジェクト固有のルールや方針 |
| `.claude/CLAUDE.md` | サブディレクトリ以下（部分的なルール） | 特定の機能領域に限定したルール |

チームで共有したいルールはプロジェクトルートの `CLAUDE.md` に書き、個人の設定はグローバルの `~/.claude/CLAUDE.md` に書く——というように使い分けます。

## まとめ: チェックリストと関連資料

### 新しいエージェントを追加する際の実践チェックリスト

- `.claude/agents/` ディレクトリに `.md` ファイルを作成する
- YAML フロントマターに `name`、`description`、`tools`、`allowedPaths` を設定する
- `description` に「どんなときにこのエージェントを呼ぶか」を明確に書く
- `allowedPaths` でエージェントが触ってよいフォルダの範囲を制限する
- フックでの制御が必要な場合は `settings.json` の `hooks` に設定を追加する
- 動作確認後に Git にコミットしてチームと共有する

### 機能・設定場所・たとえ話の対応表

| 機能 | 設定場所 | たとえ話 |
|---|---|---|
| エージェントの定義 | `.claude/agents/*.md` の YAML フロントマター | 業務説明書 |
| 使えるツールの制限 | `tools` フィールド | 使ってよいツール一覧 |
| 編集できるフォルダの制限 | `allowedPaths` フィールド | 入室できるフロア |
| プロジェクト全体の権限設定 | `.claude/settings.json` の `permissions` | 会社のアクセス権限設定 |
| 操作時の自動審査 | `.claude/settings.json` の `hooks` + フックスクリプト | 自動で動く審査係 |
| チームへの共有 | Git（GitHub）での管理 | 業務マニュアルの一元管理 |

> [!IMPORTANT]
> **覚えておきたい一文:** 「エージェントとは、Claude Code に渡す業務説明書だ」。ファイル 1 枚に「何をする人か」「どこまで触れるか」を書くだけで、専門担当者を自在に増やせます。
