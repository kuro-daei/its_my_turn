# Chapter 1: Claude Code を整える

> **この資料について**: ハンズオン開始前の事前準備資料です。Chapter 0（環境準備）が完了した後、ハンズオン当日までにこのチャプターの設定を完了させておいてください。当日は設定済みの状態で参加してください。

**所要時間**: 約 40 分
**ゴール**: CLAUDE.md、エージェント（coder）、プラグインが稼働している状態
**学ぶ Claude Code 機能**: CLAUDE.md / Agents / Plugins

---

## このチャプターで学ぶこと

- CLAUDE.md を書いてプロジェクトのルールを Claude Code に伝える方法
- プラグインをインストールして Claude Code の機能を拡張する方法
- プロジェクト専用のルールを持つエージェントを作る方法

---

Claude Code はインストールしただけでは「何も知らない新しいアシスタント」の状態です。

このチャプターでは、Claude Code に以下の 3 つを設定します。

| 設定すること | たとえ話 | 効果 |
|------------|--------|------|
| **CLAUDE.md を書く** | 新しいアシスタントへの引き継ぎメモ | プロジェクトのルールを毎回説明しなくて済む |
| **プラグインを入れる** | スマホにアプリを追加する | Git 操作や最新ドキュメント参照など便利な機能が使えるようになる |
| **エージェントを作る** | プロジェクト専用のルールを持つ担当者を用意する | 役割を持たせた Claude Code が一貫した作業をしてくれる |

40 分後には、あなたのプロジェクト専用に調整された AI 開発環境が整います。

---

## Step 1: CLAUDE.md を書く（15分）

### CLAUDE.md とは何か

CLAUDE.md（クロード・エムディー）は Claude Code が作業を始める前に必ず読む「引き継ぎメモ」です。新しく入ってきたアシスタントへの「業務マニュアル」のようなものです。

- 「このプロジェクトは TODO アプリを作っているよ」
- 「main というブランチに直接変更を保存してはいけない」
- 「TypeScript という言語を使っているよ」

こういった指示を一度書いておけば、毎回同じことを説明しなくて済みます。Claude Code は CLAUDE.md の内容をすべての作業で常に参照します。

### CLAUDE.md には 2 種類ある

| 種類 | 配置場所 | 対象範囲 |
|------|---------|---------|
| **ユーザースコープ** | `~/.claude/CLAUDE.md` | 自分のすべてのプロジェクト |
| **プロジェクトスコープ** | `プロジェクトルート/CLAUDE.md` | そのプロジェクトのみ |

> **`~`（チルダ）とは?** ホームディレクトリ（自分のユーザーフォルダ）を表す記号です。Mac なら `/Users/あなたの名前`、Linux なら `/home/あなたの名前` に相当します。つまり `~/.claude/CLAUDE.md` は「自分のホームフォルダの中の `.claude` フォルダにある CLAUDE.md」という意味です。

**ユーザースコープ（`~/.claude/CLAUDE.md`）— 自分の仕事の癖メモ**

手帳に書いておく「自分ルール」です。どのプロジェクトで作業するときも、Claude Code はこのファイルを読んでからスタートします。「返事は日本語で」「コミットメッセージはこの形式で書いて」といった、プロジェクトに関係なく自分が常に守りたいルールを書きます。

**プロジェクトスコープ（`プロジェクトルート/CLAUDE.md`）— プロジェクトの業務マニュアル**

会社やチームで共有する「業務マニュアル」です。プロジェクトルート（一番上のフォルダ）に置き、Git でチームメンバーと共有します。「このプロジェクトは何のアプリか」「main ブランチに直接コミットしてはいけない」といった、チーム全員が知っておくべきことを書きます。

> **2 種類を同時に使うと?** 両方のファイルが存在する場合、Claude Code は両方を読み込みます。より具体的（プロジェクトスコープ）な指示が優先されます。

### 1-1. ユーザースコープの CLAUDE.md を作成する

`~/.claude/` ディレクトリを作成し、CLAUDE.md を新規作成します。

```bash
mkdir -p ~/.claude
```

`~/.claude/CLAUDE.md` をテキストエディタで開き（なければ新規作成）、以下の内容を書き込みます。

```markdown
# 自分の共通ルール

- 日本語で会話する
- コミットメッセージは Conventional Commits 形式で書く（例: `feat: 機能追加`）
- 危険な操作（ファイル削除、force push など）の前には必ず確認する
```

> **Conventional Commits（コンベンショナル コミッツ）とは?** コミットメッセージの書き方のルールです。`feat:（機能追加）`、`fix:（バグ修正）`、`docs:（ドキュメント変更）` などのプレフィックスをつけることで、変更の種類がひと目でわかります。

### 1-2. Claude Code を起動する

プロジェクトルートでターミナルを開き、以下を入力します。

```bash
claude
```

[screenshot: ターミナルで `claude` を入力してインタラクティブモードが起動した画面]

プロンプト（`>` や `?` の入力待ち記号）が表示されれば起動成功です。

### 1-3. `/init` コマンドでプロジェクトスコープの CLAUDE.md を自動生成する

Claude Code のプロンプトに以下を入力します。

```
/init
```

> **`/init` って何?** Claude Code がプロジェクトのファイルを自動スキャンし、プロジェクトルートに CLAUDE.md の雛形を生成するコマンドです。

[screenshot: `/init` 実行後に CLAUDE.md が生成された様子]

> **注意:** プロジェクトがまだ空の状態でも `/init` は実行できます。その場合は最小限の雛形が生成されます。

### 1-4. プロジェクトスコープの CLAUDE.md に内容を追記する

生成された CLAUDE.md をテキストエディタで開き、以下の内容で上書きします。

**完成形のプロジェクトスコープ CLAUDE.md（コピーして使ってください）:**

```markdown
# CLAUDE.md

このファイルは Claude Code がプロジェクト作業時に参照する説明書です。

## プロジェクト概要

TODO アプリ。ユーザーがタスクを追加・完了・削除できる Web アプリケーション。
非エンジニアが Claude Code の使い方を学ぶためのデモプロジェクトでもある。

## Git ルール（MUST）

- **main ブランチでの commit / push は絶対禁止**
- 作業前に必ず `git branch --show-current` でブランチを確認すること
- main にいた場合はブランチ作成を提案して作業を止めること
- ブランチ命名規則: `feature/機能名`、`fix/修正内容`、`docs/内容`
- コミットメッセージは Conventional Commits 形式を使う（例: `feat: TODO 追加機能を実装`）

## 設計書

- `docs/plans/` は機能の設計書を置く場所
- 機能を実装する前に、ここに設計書を書く（Claude Code に書かせてもよい）
- 実装を担当するエージェントはこのフォルダを参照してから作業を始める
```

### 1-5. 確認する

Claude Code のプロンプトで以下を入力します。

```
このプロジェクトは何のためのアプリですか？概要を教えてください。
```

[screenshot: CLAUDE.md 記載後に Claude Code が的確な回答を返している画面]

> **体験ポイント:** CLAUDE.md 追記前の回答と比べてみましょう。「業務マニュアル」を渡す前と後で、アシスタントの答えの具体性がまったく変わるはずです。

### Step 1 の確認ポイント

- [ ] `~/.claude/CLAUDE.md`（ユーザースコープ）が作成されている
- [ ] プロジェクトルートに `CLAUDE.md`（プロジェクトスコープ）が存在する
- [ ] Claude Code に「このプロジェクトは何のためのアプリですか？」と聞いて、プロジェクト概要が含まれた回答が返ってくる
- [ ] Claude Code に「main ブランチにコミットしてください」と頼んだとき、警告が出ることを確認する

## Step 2: プラグインを入れる（10分）

### プラグインとは何か

プラグインは、Claude Code に機能を追加する拡張パックです。

> **スマホにアプリを追加するイメージです。** スマホを買ったばかりのときは基本的な機能しか使えませんが、アプリを追加するほどできることが増えます。プラグインも同じで、インストールするだけで Claude Code の能力が広がります。

プラグインは以下のコマンドでインストールできます。

```bash
claude plugin install <プラグイン名>
```

ここでは 3 つのプラグインをインストールします。

### 2-1. claude-md-management をインストールする

**CLAUDE.md を自動で更新・改善してくれるプラグインです。**

- セッション中に学んだことを CLAUDE.md に自動反映できます
- CLAUDE.md の品質チェックを実行できます

```bash
claude plugin install claude-md-management
```

インストール後、Claude Code のプロンプトで以下のコマンドを試してみましょう。

```
/claude-md-management:revise-claude-md
```

> **何が起きるか:** Claude Code が現在の CLAUDE.md を読み込み、改善できる点を提案したり、セッション中に判明した情報を追記したりします。

### 2-2. commit-commands をインストールする

**Git のコミットや PR 作成を自動化するプラグインです。**

> **Git（ジット）とは?** ファイルの変更履歴を管理するツールです。「コミット」は変更を記録する操作、「PR（プルリクエスト）」は変更をチームに共有して取り込んでもらうための申請です。

- コミットの作成
- プッシュ（変更をサーバーに送ること）と PR の作成をまとめて実行
- 不要なブランチの掃除

```bash
claude plugin install commit-commands
```

インストール後に使えるようになるコマンドの例:

| コマンド | 内容 |
|---------|------|
| `/commit` | 変更をコミットする |
| `/commit-push-pr` | コミット・プッシュ・PR 作成を一気に実行する |

### 2-3. context7 をインストールする

**プログラミングライブラリの最新ドキュメントを検索できるプラグインです。**

> **ライブラリとは?** プログラムを作るときに使える「部品集」です。Next.js や React などが代表的なライブラリです。

- 1000 以上のライブラリの最新マニュアルを瞬時に参照できます
- Claude Code が古い情報で答えるのを防ぎます

```bash
claude plugin install context7
```

インストール後は、Claude Code に普通に質問するだけで自動的に最新ドキュメントを参照します。

```
Next.js の App Router について教えてください
```

> **体験ポイント:** context7 なしで同じ質問をしたときと比べてみましょう。最新の公式ドキュメントをもとに回答するようになり、情報の正確さが上がります。

### Step 2 の確認ポイント

- [ ] 3 つのプラグインがインストールされている（`claude plugin list` で確認できます）
- [ ] `/commit` コマンドが認識される（プロンプトで `/commit` と入力して補完が出るか確認）

## Step 3: エージェントを作る（10分）

### エージェントとは何か

エージェントは、Claude Code にプロジェクト専用のルールを持たせた「担当者」を作れる仕組みです。

> **社内の担当者メモのようなものです。** 「実装担当の田中さんは設計書を見て作業する」「コードだけ触れる」といったルールを書いておくと、Claude Code がその通りに動きます。

エージェントは `.claude/agents/` フォルダに `.md` ファイルとして定義します。

### 3-1. エージェント用ディレクトリを作成する

```bash
mkdir -p .claude/agents
```

### 3-2. coder エージェントを作成する

`.claude/agents/coder.md` を以下の内容で作成します。

```markdown
---
name: coder
description: 設計書を読んでコードを実装する担当者。docs/plans/ にある設計書を参照し、プロジェクトのコーディングルールに従って実装する。
tools:
  - read
  - write
  - edit
  - bash
  - glob
  - grep
---

あなたは実装担当者です。作業前に docs/plans/ の設計書を参照します。プロジェクトのコーディングルールに従って実装し、不明点は確認してから進めます。日本語で回答します。
```

### 3-3. 動作確認

Claude Code のプロンプトで以下のように試してみましょう。

```
coder として、src/utils.ts に「入力された文字列を大文字に変換する関数」を追加してください
```

[screenshot: coder エージェントが役割に沿って応答している様子]

> **体験ポイント:** エージェント名を指定しない場合と比べてみましょう。coder として呼び出すと、設計書を参照する姿勢や実装に特化した回答になるはずです。

エージェントは必要に応じて増やせます。たとえばレビュー専用の `reviewer` や設計専用の `architect` を追加すれば、役割ごとに異なる動きをさせることができます。

### Step 3 の確認ポイント

- [ ] `.claude/agents/` ディレクトリが作成されている
- [ ] `coder.md` が存在する
- [ ] Claude Code のプロンプトで `coder として` と指定して呼び出せる

## うまくいかないときは

### Claude Code が起動しない

```bash
# インストールの確認
npm list -g @anthropic-ai/claude-code

# 再インストール
npm install -g @anthropic-ai/claude-code

# バージョン確認
claude --version
```

### プラグインがインストールできない

- インターネット接続を確認する
- `claude plugin list` を実行してインストール済みの一覧を確認する
- エラーメッセージをそのままコピーして Claude Code に「このエラーの意味を教えてください」と聞いてみる
- わからなければメンターに声をかけてください

### エージェントが認識されない

- `coder.md` のファイル名と `.md` 拡張子が正しいか確認する
- `.claude/agents/` の直下にファイルがあるか確認する（サブディレクトリ内には置けません）
- YAML フロントマター（`---` で囲まれた部分）の形式が正しいか確認する

> **YAML フロントマターとは?** ファイルの先頭に書く設定情報です。`---` で囲まれた中に、エージェントの名前や使えるツールなどを書きます。

## このチャプターのまとめ

このチャプターでは、Claude Code を「使えるツール」から「プロジェクトに合わせて動く環境」に整えました。

- **CLAUDE.md（2 種類）**: `~/.claude/CLAUDE.md` に自分の共通ルールを、プロジェクトルートの `CLAUDE.md` にチーム共通のプロジェクトルールを書くことで、毎回同じことを説明しなくて済むようになりました
- **プラグイン**（claude-md-management・commit-commands・context7）: Claude Code に機能を追加し、CLAUDE.md の自動改善・Git 操作の自動化・最新ドキュメントの参照ができるようになりました
- **エージェント**（coder）: プロジェクト専用のルールを持つ担当者を `.claude/agents/` に定義することで、役割を意識した一貫性のある作業を Claude Code にさせられるようになりました

Chapter 1 で作った設定は、次の Chapter 2 以降で活きてきます。CLAUDE.md の Git ルールがブランチ管理を自動化し、エージェントが専門的な役割でサポートします。
